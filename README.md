# PyTorch for Humans

A free, friendly course on PyTorch and machine learning that explains the **why**: real-life
analogies, interactive sims you can break, and real code. Published as a website (GitHub Pages)
plus runnable Kaggle notebooks.

Every lesson follows the same flow: **see it → build it from scratch (NumPy) → use the real tool (PyTorch).**

| Layer | Where it runs | Why |
| --- | --- | --- |
| Visual sims (Canvas + TypeScript) | Browser | Instant intuition, works offline |
| "From scratch" Python (NumPy) | Browser, via [Pyodide](https://pyodide.org/) | Edit and run code with zero setup |
| Real PyTorch | Kaggle notebook / your machine | PyTorch has no official browser build |

## Run the website locally

Needs **Node.js 22.12 or newer** (Astro 7 requirement; CI uses Node 24).

```bash
npm ci              # install (from the repo root: it's an npm workspace)
npm run dev         # http://localhost:4321 with live reload
npm run build       # production build into site/dist/
npm run preview     # serve the production build
npm run check       # type-check
npm test            # Vitest: sim maths vs PyTorch golden values, live sims vs facts
npm run test:e2e    # Playwright (after `npm run build`): sim behaviour, narration snapshots,
                    #   Pyodide cells, quiz, offline, 375px light/dark. First time:
                    #   npx -w site playwright install chromium
                    # Changing narration on purpose? UPDATE_NARRATION=1 npm run test:e2e -- narration
```

The `.ipynb` download button appears once the notebooks are built into the site (see below, `--site`).

## Run the Python side locally

Needs **Python 3.12+**.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

python scripts/test_snippets.py                     # run snippets + facts.py; fail if outputs are stale
python scripts/test_snippets.py --update            # after changing code: regenerate outputs + facts.json
python scripts/build_notebooks.py                   # .py → build/notebooks/*.ipynb
python scripts/build_notebooks.py --execute         # ...run them, and check included cells print
                                                    #    exactly the website's outputs (what CI does)
python scripts/build_notebooks.py --site            # ...and copy them into the site for download
```

On Windows, set `PYTHONIOENCODING=utf-8` if your console chokes on emoji in the output.

## Publish to Kaggle

```bash
pip install -r requirements-kaggle.txt
kaggle auth login           # or any auth method from the Kaggle CLI docs; credentials never go in this repo
KAGGLE_USERNAME=<you> COURSE_URL=https://<you>.github.io/<repo>/ python scripts/build_notebooks.py --kaggle
python scripts/kaggle_push.py --dry-run
python scripts/kaggle_push.py
```

`--kaggle` refuses to build unless both variables are set, and `kaggle_push.py` refuses any
notebook that still contains a `{{…}}` placeholder or `# include:` line. Notebooks are created **private** (`"is_private": "true"`). Check that one ran with
`kaggle kernels status <you>/<slug>`, then make it public on Kaggle.

## Deploy the website

The full step-by-step launch checklist (GitHub Pages, what passing CI runs look like, the first
Kaggle push and what to check on the notebook page) is in [docs/LAUNCH.md](docs/LAUNCH.md).

1. Push this repo to GitHub.
2. **Settings → Pages → Source: GitHub Actions.**
3. Optional: **Settings → Secrets and variables → Actions → Variables**, add `KAGGLE_USERNAME`
   to turn on the "Open in Kaggle" buttons.

`deploy-site.yml` works out the Pages URL and base path automatically. Pull requests get a build
check without deploying.

## Sims

Every interactive sim follows [docs/SIM_STANDARD.md](docs/SIM_STANDARD.md): narrated phases,
nothing autoplays, numbers and labels on show, a log of key moments, keyboard + reduced-motion
support, and maths checked against real PyTorch. All sims also live in the **Sim gallery** section
of the site.

## Add a lesson

```bash
python scripts/new_lesson.py foundations 2 "Tensors"
```

This creates `course/foundations/02-tensors/` from `templates/lesson/`. The lesson appears in the
sidebar automatically (ordered by the `02-` prefix) at `/foundations/tensors/`. Fill in the TODOs,
keep the 8-section structure (see the "How lessons work" page), and run the tests.

Rules that keep the course trustworthy:

- **Every code cell lives in a real `.py` file** under `snippets/`, imported into the page with
  `?raw`, so CI runs exactly what learners see. Browser snippets may only import NumPy + stdlib.
  The notebook pulls the same files in with a cell containing only `# include: snippets/…`.
- **Never paste outputs.** Show them with `<Output text={…} />` from `snippets/outputs/`, which
  `test_snippets.py --update` regenerates. CI fails if they're stale, and fails if the notebook
  prints anything different.
- **Never type a computed number into prose.** Derive it in `facts.py` and quote it from
  `facts.json`: `{facts.x.y}` in MDX, `{{facts.x.y}}` in notebook markdown.
- **Declare every claim the prose makes** (e.g. "this preset explodes") in `data.json` under
  `"claims"`, as a `check` expression over `facts.json`. `facts.py` only computes; the facts
  runner evaluates the claims and fails CI if one is false (sims do the same in `config.json`).
- **Training loops print loss, w and b at the same moment** (before the update step).
- **Notebooks must run top to bottom on Kaggle CPU with no internet and no files.** Use only
  libraries Kaggle preinstalls (torch, numpy, matplotlib, plotly).
- **Memes** are recreated as text/CSS, never copied images, and always explained.
