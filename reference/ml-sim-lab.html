Feasibility study · interactive animations for the PyTorch course

ML Sim Lab

Can we teach ML with live animations that people can poke at in a browser tab, and can they actually follow what's happening? There are four working prototypes below. Each one has a narrator that explains every phase as it happens.

Works Live JS simsOptimizers, backprop, convolution and live network training all run smoothly with no libraries.
Heavy Real pretrained modelsPossible with ONNX Runtime Web or Transformers.js, but the downloads are tens to hundreds of MB. Put them behind a button.
Not possible PyTorch in the browserPyTorch still doesn't run in Pyodide. Use NumPy in the browser, and real PyTorch on Kaggle.

Four working prototypes

Every sim has a narrator box (the coloured caption) that says what is happening and why. Sims with stages can be stepped one at a time. The ones that run continuously have a speed control and a log of key moments.

Foundations · Autograd · step-through

Backprop as a chain of blame

A one-neuron model learns to output 7 when it sees 2. Press Next to walk through one full training round: the forward pass, then the backward pass, then the update. Every step shows the actual arithmetic.

loss = (w * x + b - y) ** 2 # forward: compute + record the graph
loss.backward() # backward: fills w.grad and b.grad
with torch.no_grad():
w -= lr * w.grad; b -= lr * b.grad # update, lr = 0.02
w.grad.zero_(); b.grad.zero_() # reset, or the next round's grads pile on top
Rendering
Inline SVG with CSS transitions. A script of 11 narrated steps is rebuilt from the live numbers each round.
Accuracy
The gradients follow the same chain rule PyTorch autograd uses. The numbers match w.grad and b.grad exactly.

      Animation rules for every course sim

      These came straight from your feedback that people couldn't follow the first version. They become part of the lesson template.

      Narrate every phase

      A caption box always says what is happening right now and why it matters, in plain words. It updates on every step or phase change.

      Slow by default, steppable always

      Anything with stages gets Next and Back buttons. Anything continuous gets a speed control and a Step button. Nothing autoplays.

      Show the numbers behind the picture

      The arithmetic strip in the convolution sim, the gradient values in backprop, and the loss charts. The picture builds intuition and the numbers make it trustworthy.

      Annotate on the canvas

      Downhill arrows, the dashed valley floor, the decision line, rings around mistakes. Put labels where the eye already is.

      Log key moments

      Overshoots, divergence, zigzags, accuracy milestones. Each gets a timestamp so learners can look back after missing something.

      One thing changes at a time

      Highlight the one active node, window or phase. Everything else stays still and muted.

      How this plugs into the Astro site

      One sim = one module

      Each sim is framework-free TypeScript exporting mount(el, options) and returning a destroy(). Astro loads it with client:visible.

      A shared sim kit

      Narrator box, event log, speed control, Back/Next stepper, theme-token reader, HiDPI canvas sizing, and a pause when scrolled away. Build it once and every sim gets it.

      Correctness guardrail

      A Python script in CI computes reference values with real PyTorch (gradients, conv outputs, optimizer steps) and saves them as JSON. JS unit tests must match them, so no sim teaches wrong maths.

      Weight budget

      Under about 100 KB of JS per lesson. Pyodide loads on the first "Run" click, in a Web Worker. Model downloads sit behind a button that shows the size.

      Accessibility

      The narrator is an aria-live region, so screen readers hear every phase. Controls are keyboard-operable, and reduced motion skips transitions.

      Kaggle side

      Published Kaggle notebooks are static, so use Plotly animation frames or matplotlib to_jshtml(). Put the narration in markdown cells between the frames.

      Prior art worth studying

      • CNN Explainer runs a pretrained CNN in the browser and moves smoothly between the overview and the maths.
      • Transformer Explainer runs live GPT-2 in the browser and reached about 490k users.
      • Interactive Tools collection is a big index of existing ML visualizers. Check it before building.
      Prototypes are self-contained: plain JS, no libraries. The PyTorch-in-browser verdict is based on Pyodide's documented cffi blocker; re-check when Pyodide releases new versions.
